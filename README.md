## Текущая стадия

Комплект содержит исходники основы: Django, PostgreSQL, миграцию автомобиля,
HTML-каталог и /health/. Основа проверена M2 на Ubuntu с реальной PostgreSQL;
результаты проверок приведены ниже.
Полные бронирования, аренды и механизмы предметных операций планируются.
Будущие проверки D не являются выполненными тестами.

## Проверка зафиксированной основы

Зависимости установлены на Ubuntu с Python 3.13; pip check успешен. Выполнены пять тестов основы с изолированной SQLite, все успешны; Django system check не выявил проблем. Это не подтверждает будущие механизмы D или блокировки PostgreSQL. Также подтверждены реальная PostgreSQL, миграции, чтение автомобиля каталогом и ответы health 200, POST без CSRF-токена 403, с корректным токеном 405, неизвестный адрес 404. Команды воспроизведения — в PROJECT.md. Установка повторена в чистой среде из requirements.txt. Через настоящий HTTP-сервер проверены безопасные 503 каталога и health при остановке БД и возврат 200 после её запуска; отсутствие обязательных секретов прекращает инициализацию.

В [D-02: пограничный случай](decisions/D-02.md#case-late-return) разобраны
соседние интервалы, поздний возврат и неподтверждённый осмотр. Уточнены
T-04, SR-06/SR-14, решение и будущая проверка V-14. В
[сравнении A/B](decisions/D-02.md#alternatives) сопоставлены блокировка
автомобиля и оптимистическая версия: компромисс, допущения, условие пересмотра
и V-15. Это два разных основания повышенного уровня, не выполненные тесты
бронирования. Индивидуальное понимание и вклад подтверждаются на защите.

Новые коммиты не заменяют автоматически ранее переданный оцениваемый hash.
Если версия уже сдана, её замену согласуют с преподавателем. Перед сдачей
команда завершает декларацию AI_USAGE и подтверждает фактический статус
ранней калибровки: эти сведения нельзя получить из исходного кода.
